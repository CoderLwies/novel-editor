# 字舟 · 网文小说编辑器

<img src="public/logo.png" alt="字舟 logo" width="96" align="right" />

面向网文连载作者的桌面写作工具。**编辑器优先**——把码字、章节管理、设定集与大纲做扎实，AI 作为叠加层辅助策划与一致性校验。

Electron 桌面应用 · React + Vite + TypeScript · 无后端，数据保存在本地。

---

## 特性

### 写作核心
- **书架**：多作品管理，封面色 / 连载状态 / 月更目标进度一目了然；启动恒落书架；最近打开快捷行
- **三栏工作台**：卷-章树 · 沉浸编辑器 · 侧栏（大纲 / 角色 / 设定 / 伏笔）
- **码字统计**：实时字数与速度、日更目标、连续更新天数、全书纲覆盖率；达成日更目标提醒一次
- **写作体验**：跨章节全文搜索/替换（命中跳转定位）、章节快照与版本历史回滚、撤销/重做（Ctrl+Z/Y）、落盘同步状态指示、专注模式（隐藏目录侧栏+正文居中）、打字机滚动
- **明暗主题**、可调字号
- **性能**：编辑器 store 提交与 localStorage 落盘均防抖合并（200–300ms），输入期不做全量序列化；页面隐藏/卸载前强制 flush 不丢字
- **统一搜索（Ctrl+K）**：章节标题 / 正文 / 角色 / 设定 / 伏笔一框检索；正文命中跳章并定位选区，元数据命中切对应侧栏 tab 并注入过滤词
- **新手引导与帮助**：首次启动五步引导；顶栏帮助页汇总快捷键、功能入口与常见问题

### 大纲体系
- **卷纲**：概括 / 目标 / 核心冲突
- **结构化章纲**：目标 / 冲突 / 转折 / 结尾钩子 / 视角人物 / 出场角色 / 伏笔埋收挂接 / 纲状态（计划中 · 已写 · 已修）
- **全书大纲表**：拖拽排序、跨卷移动、行内改纲状态、点击回正文
- **伏笔管理**：埋设/回收双挂接链路、按章序埋收时间线、重要度（主线/支线/细节）、关联角色、跨度与"回收早于埋设"等告警
- **导出**：全书大纲 / 设定集 / 伏笔表 Markdown

### 角色与设定体系
- **角色卡**：定位 / 状态（存活·死亡·失踪·退场+色点）/ 别名（参与正文命中）/ 外貌·性格·背景·动机·能力·口头禅六维折叠字段 / 关系网（可跳对方卡）与 SVG 关系图 / 成长弧线（阶段+关联章）/ 出场章节与统计 / 相关伏笔 / AI 补全
- **伏笔↔设定互挂**：伏笔卡关联设定 chips，设定卡反向显示相关伏笔
- **故事时间**：章纲可填"第 N 天"，巡检对时间倒序告警
- **设定集**：五类（地点·物品·势力·规则·功法）/ 当前状态 / 按名称命中正文的出现章节反向索引
- **检索**：角色 / 设定 / 伏笔三个 tab 均支持搜索过滤

### 参考库（导入他人作品做拆解分析）
- **导入**：单个 TXT / MD（**自动探测编码**，UTF-8 失败回退 GB18030）或整本书目录（每章一个文件，自然排序，带读取进度）。识别卷标、章标、序章 / 楔子 / 番外 / 后记、`正文 第X章`、`Chapter N`、Markdown 标题分卷。误删可用「接入已有目录」重新绑定，分析产物继续可用
- **只存目录不入书架**：参考书单独落盘，不参与日更与字数统计，与自己的作品完全隔离
- **阶段一 · 结构与节奏（纯本地，0 token）**：章长均值 / 标准差 / 分位数、卷规模、固定 20 章粒度的节奏窗口、张力标点密度与留白率（均标注为**弱信号**，反映叙述层而非情节强度）
- **阶段二 · 要素抽取（AI）**：角色六维 + 别名 + 出场章、设定五类 + 子类型、伏笔埋收章与跨度。跨批次按**名字与别名精确合并**，不做模糊匹配。产物落盘后可随时回看要素详情（角色/设定/伏笔三个页签，支持搜索；**空字段代表原文未交代，不是抽取遗漏**）
- **阶段三 · 情节链（AI）**：情节拍固定六类枚举，每拍带 `signal`（可识别特征）与 `cost`（硬性要求）；跨批次延续合并为同一拍；末次调用把有序拍组织成叙事线并抽出**不含原文的可复用骨架**
- **写作时参考面板**（侧栏「参」按钮，**只读**；三者回答不同问题，互斥显示）：
  - 卷纲：每卷情节配比 + 可借骨架 —— **纯本地计算，不花 token**
  - 设定：同类设定的要素清单 + 缺口检查（关键词匹配判定，结果可解释）
  - 章纲：**拿当前章正文比对参考书特征，定位"你现在写到第几拍"**；把握不准时明说而不是硬给答案
- **AI 任务队列**：并发 3 / 每批 4 章 / 断点续跑 / 费用上限（默认 ¥50，可在成本确认弹窗调整）/ 失败批次显式可重跑。超预算**暂停而非终止**，调高上限再点一次即从断点续跑
- **分析范围分档**：每卷前 20 章 / 前 100 章 / 全书，费用按所选范围预估；换档位后旧缓存自动作废，不会串档

### 落盘与导入导出
- 作品可**绑定本地目录**，编辑即自动同步落盘：
  - `book.json`（项目元数据，version 2）
  - `chapters/NNNN_标题.md`（正文 + YAML frontmatter 携带章纲与伏笔埋收字段）
- **外部编辑器改 md 可回读**：重新导入时 frontmatter 优先合并
- 导入：字舟项目目录 / 单个 TXT·MD（自动拆卷章）；兼容旧版 v1 项目与旧存储键自动迁移
- 导出：项目包 / 纯 TXT / Markdown / 全书大纲 / 设定集 / 伏笔表 / **EPUB 电子书**（标准 EPUB3，含导航与卷章结构）

### AI 辅助
- **拆章纲**（卷级）：依据总纲 + 卷纲规划新章节，预览多选后建章
- **走向分支**（章级）：为单章推演多个剧情分支，一键采用
- **写后回写**（章级）：依据正文归纳实际 synopsis / 转折 / 钩子，并按名字+别名快照出场人物
- **选中文本操作**：编辑器选中正文即出现 续写 / 润色 / 审查（结果可编辑再采用）
- **AI 角色卡补全**：依据出场章节正文归纳外貌/性格/背景/动机/能力/口头禅六维，可编辑后「填入空缺」或「覆盖采用」
- **AI 设定生成/补全**：依据总纲与已有设定批量生成世界观候选（预览多选入库）；单设定依据正文命中片段归纳描述与当前状态
- **一致性巡检**：有正文仍"计划中"、挂角未出场（含别名）、同章混用称呼、伏笔埋设超 10 章未收 / 登记未挂接 / 回收早于埋设 / 状态与挂接不符、已死亡角色仍挂接最新章、空卷

走 OpenAI 兼容协议（`POST {baseUrl}/chat/completions`），Base URL 预填 DeepSeek 官方、可改为兼容中转站；模型提供预设（deepseek-flash / chat / reasoner）并可自填。

### 分发
- Windows NSIS 安装包：简体中文界面、安装时自选目录、嵌入应用图标
- 自动更新：electron-updater（generic provider；部署时把 `build.publish` 的 url 替换为自有更新服务器）。文件菜单「检查更新」，启动后亦自动检查；下载完成提示重启安装
- 首包瘦身：jszip 等重依赖动态 import，仅导出 EPUB 时加载

## 快速开始

```bash
# 安装依赖（.npmrc 已配置 npmmirror 镜像）
npm install

# 浏览器开发（热更新）
npm run dev

# Electron 桌面开发
npm run electron:dev

# 构建渲染层
npm run build

# 打包桌面安装包（输出到 release/）
npm run electron:build
```

类型检查：`npm run typecheck`。

## 落盘格式

绑定目录后结构如下：

```
<作品目录>/
├── book.json                 # format: zizhou-project, version: 2
├── chapters/
│   ├── 0001_第一章 标题.md
│   └── 0002_第二章 标题.md
└── history/                  # 章节快照（index.json 元数据 + 每快照一个 md）
```

章节 md 以 frontmatter 携带章纲，正文在其后：

```markdown
---
title: 第一章 标题
outlineStatus: written
synopsis: 一句话概括
goal: 本章目标
turning: 转折点
hook: 结尾钩子
pov: 视角人物
cast: [char_1]
foreshadowIds: [fs_1]
foreshadowPayoffs: [fs_2]
---

正文内容……
```

`foreshadowIds` 为本章埋设的伏笔、`foreshadowPayoffs` 为本章回收的伏笔。外部工具直接编辑该 md（含 frontmatter）后，在字舟中重新导入即可回读。

### 正文的存放位置

**localStorage 只存元数据，章节正文一律落盘。** 实测一部 300 章 / 105 万字的作品，状态体积从 2.27 MB 降到 0.26 MB（当前编辑章的正文作为卸载兜底保留在 localStorage）。

- 输入时只**重写改动的那一章**，不是全书文件
- 未绑定目录的作品启动时自动分配到 `<userData>/books/<id>/` 并迁移落盘
- 浏览器端无文件能力时退回 localStorage 全量模式

### 参考书目录

参考作品绑定目录后：

```
<参考目录>/
├── reference.json             # format: zizhou-reference + 当前分析阶段
├── chapters/NNNN_标题.txt     # 拆好的原文（以 UTF-8 重写，无损）
└── analysis/
    ├── structure.json         # 阶段一：结构与节奏（纯本地）
    ├── elements.json          # 阶段二：角色 / 设定 / 伏笔
    ├── plot.json              # 阶段三：情节拍 / 叙事线 / 骨架
    ├── checklists.json        # 设定要素清单（按 category:subtype 索引）
    ├── checkpoint-<stage>.json# 分阶段断点，批大小变更即作废
    └── raw/<stage>-NNNN.json  # 每批原始输出，断点恢复靠重放而非重跑
```

## AI 配置

工作台顶栏 → 「AI 接口设置」：

- **Base URL**：默认 `https://api.deepseek.com`，可改为任意 OpenAI 兼容中转
- **API Key**：DeepSeek 密钥（本地免鉴权服务可留空）
- **模型**：预设 `deepseek-flash`，也可自填兼容模型名

配置仅存本机 localStorage；请求由桌面端直连所填地址，不经过任何第三方服务器。

**成本控制**：参考库的每个 AI 阶段在开始前都会显示费用区间（区间而非定值——模型输出长度不可预测），运行中实时累计，超预算即**暂停**并保留全部进度，可加预算后续跑。按 DeepSeek 现行价，一部 286 章 / 90 万字的作品，结构统计 0 元、要素抽取约 ¥0.26、情节链拆解约 ¥0.49。

> DeepSeek 于 2026-08-17 调整定价并启用峰谷分时定价（高峰 9:00–12:00 / 14:00–18:00 翻倍）。成本预估已按峰谷分别计算，界面会提示当前是否处于高峰。单价做成了可配置项而非写死——调价频繁，硬编码会让预算换算悄悄失真。
